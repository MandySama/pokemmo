# PokeMMO

基于 Java 复刻 PokeMMO，目前已接通桌面客户端、登录服务和游戏服务的入服流程。

## 项目结构

| 目录 | 说明 |
| --- | --- |
| `client` | 桌面窗口、渲染、登录界面、音频播放与网络认证 |
| `twl-core` | TWL 核心源码模块，通过 Maven 模块依赖提供给客户端 |
| `data` | 外部资源，包括窗口图标、主题、字体、背景图片和语言 XML |
| `roms` | 导入的 ROM 文件，在首次导入时创建 |
| `config` | 客户端本地配置，在首次导入时创建 |
| `protocol` | 客户端、登录服务与游戏服务共用的封包、握手、加密通道及入服凭证 |
| `sever/login` | TCP 登录服务、内存账号与凭据校验 |
| `sever/game` | 游戏服务监听、入服验证、在线会话和心跳 |
| `sever/chat` | 聊天服务模块 |

`sever` 为当前项目使用的目录及模块名称。

## 当前实现

| 功能 | 已实现内容 |
| --- | --- |
| 桌面窗口 | 窗口图标、主屏工作区居中及窗口缩放适配 |
| UI 与渲染 | TWL 控件、XML 主题、GLFW/OpenGL 渲染及 FreeType 字体绘制 |
| 界面文本 | 自动发现语言 XML，按字符串 ID 读取文本，支持切换与主语言回退；当前提供简体中文 |
| 登录画面 | Logo、循环滚动的图片背景、左上角已加载 ROM 名称及右下角按钮区 |
| 公告列表 | 左下角静态公告标题与六条公告，半透明底色，随窗口大小定位；文本由语言 XML 提供 |
| 黑白 ROM 3D 背景 | 从已导入的黑白 ROM 的 NitroFS 定位 NARC 资源包，读取两套标题场景的模型、调色板纹理、骨骼动画、纹理切换动画和镜头轨迹；随机选择场景，以每秒 30 帧循环播放，支持窗口缩放；后台解析，绘制线程上传和释放纹理；导入后自动加载，无可用场景时显示图片背景 |
| 关都出生地图预览 | 从已导入的火红 ROM 定位地图表，读取主角家二楼的地图布局、主副图块集和 BGR555 调色板，解压 LZ77 像素，处理图块翻转、透明色及上下层叠加；使用最近邻采样、整数倍缩放居中绘制 |
| 火红地图公共绘制规则 | 按布局编号应用 165 条地图格修正，按季节、图块集和调色板编号应用 707 条颜色覆盖；读取 7 组 ROM 图块动画，以 300 毫秒间隔循环播放；区分底层、普通上层及高处上层，按地图类型应用昼夜或水下染色，并叠加夜间窗户和灯光贴图；规则位于 `data/maps/fire-red.xml`，夜间图集位于 `data/sprites/overlays*.pak` |
| 登录音乐 | 从已导入黑白 ROM 读取 SDAT，使用 SSEQ 原生合成器与 OpenAL 循环播放；普通曲目与低概率备用曲目，管理窗口和服务器选择期间连续播放；音乐音量默认 50%，默认在窗口失焦时静音，重新激活后按当前音量继续播放；支持 ROM 切换和退出清理 |
| 登录表单 | 用户名、密码、记住我和登录按钮，以及输入、焦点切换、选区、剪贴板及右键菜单交互 |
| 记住我 | 密码认证成功后由登录服务签发凭据，保存到 `config/savedcredentials.properties`；支持已保存账号下拉、上次账号恢复、“已保存”密码占位、其他用户名及清除已存密码；凭据登录不发送密码，本地不保存密码或摘要，服务端密钥或账号密码变化后凭据失效 |
| 登录状态与通知 | “登录中...”状态、失败后的表单恢复，以及可堆叠、自动消失的通知 |
| 客户端管理窗口 UI | 语言下拉列表、ROM 文件选择和信息弹窗；未导入时显示“必需 / 可选”，导入后显示“信息”；无标题确认弹窗居中显示并遮暗背景；取消选择显示通知；打开 ROM 文件夹提供悬浮提示并打开系统文件管理器 |
| ROM 文件导入 | 按文件签名识别压缩包，读取文件头校验 GBA 游戏代码和修订号、NDS 游戏代码及区段范围；后台经 `roms/importing.tmp` 和 `_import` 文件完成导入，按类型编号命名，通过 `config/main.properties` 的 `client.roms.*` 保存绝对路径，兼容迁移旧选择记录，重启后重新校验并恢复，导入失败保留旧记录 |
| MOD 管理窗口 UI | 空列表提示、获取与导入 MOD、打开 MOD 文件夹、调试详情复选框、保存按钮和关闭操作 |
| 设置窗口 | 影像、声音、界面、游戏、控制、语言、聊天、工具和联动分类，以及下拉、勾选、数值调整、滚动和关闭交互；右上角帧率显示与“显示FPS计数器”选项关联，默认关闭、切换即时生效，每累计绘制 100 帧，以 `100 ÷ 耗时（秒）` 计算平均 FPS 并刷新，保留两位小数，三个音量数值框支持点击输入、回车或失焦确认、Esc 取消及 0–100 范围限制；帧率显示、音乐音量与失焦静音即时生效，“保存”写入 `config/main.properties` 并在下次启动恢复，保留 ROM 路径等其他配置 |
| 登录认证 | 异步 TCP 连接、ECDSA 服务端签名验证、ECDH 密钥交换、AES-CTR 加密与 HMAC 封包校验；内存账号验证，登录中状态、认证后的服务器选择切换，以及密码错误、系统错误和通信失败提示，默认地址 `127.0.0.1:2106` |
| 服务器选择 | 登录成功后显示名称、实时负载状态与登录按钮，每五秒刷新；选择节点后领取短期凭证，连接独立 game 服务；支持异常提示及关闭返回登录页 |
| 游戏服务连接 | ECDSA/ECDH 握手、AES-CTR 与两字节 HMAC、服务端未压缩标记、签名凭证有效期与一次性验证、在线容量和重复账号检查、加密心跳与断线清理 |

## 开发与运行

环境要求：JDK 21、Maven，以及支持 OpenGL 的 Windows 桌面环境。当前 LWJGL 原生依赖按 Windows 配置。

在项目根目录编译：

```shell
mvn compile
```

在 IntelliJ IDEA 中打开根目录的 `pom.xml` 并加载 Maven 项目，使用 `client` 模块的类路径运行：

```text
top.totodile.pokemmo.Main
```

运行配置的工作目录设为项目根目录；也支持从 `client` 目录运行。外部 `data` 目录需保留，资源不会自动打入客户端 JAR。

可通过运行配置的 VM options 指定登录服务器：

```text
-Dpokemmo.login.host=127.0.0.1 -Dpokemmo.login.port=2106
```

Java 和 XML 尽量采用 IntelliJ IDEA 默认格式。控件尺寸、焦点规则、通知时序等实现细节在对应代码与主题注释中维护。

先在客户端管理中导入火红 ROM，再给同一入口的运行配置添加以下 VM option，即可打开关都出生房间预览：

```text
-Dpokemmo.preview.map=kanto
```

预览读取本地 ROM 配置，不需要连接服务器；移除此参数后恢复登录界面和登录服务。

可通过以下参数指定地图和预览环境；默认地图组为 `4`、地图编号为 `1`，季节为夏季，时间为中午 12:00。季节编号 `0/1/2/3` 分别对应春、夏、秋、冬。

| VM option | 说明 |
| --- | --- |
| `-Dpokemmo.preview.group=3` | 地图组编号；组 `3` 包含室外城镇和道路 |
| `-Dpokemmo.preview.id=0` | 组内地图编号；`3/0` 为真新镇，`3/3` 为华蓝市 |
| `-Dpokemmo.preview.season=3` | 季节编号 |
| `-Dpokemmo.preview.hour=0` | 小时，范围 `0～23` |
| `-Dpokemmo.preview.minute=0` | 分钟，范围 `0～59` |
| `-Dpokemmo.preview.enhanced=false` | 关闭增强，显示原始 ROM 静态地图；默认 `true`。对比时保持其他参数相同，窗口标题会标明当前模式 |

例如查看真新镇的冬季夜景：

```text
-Dpokemmo.preview.map=kanto -Dpokemmo.preview.group=3 -Dpokemmo.preview.id=0 -Dpokemmo.preview.season=3 -Dpokemmo.preview.hour=0
```

先使用 `sever/game` 模块的类路径启动游戏服务：

```text
top.totodile.pokemmo.game.Main
```

再使用 `sever/login` 模块的类路径运行登录服务入口，最后启动客户端：

```text
top.totodile.pokemmo.login.Main
```

默认内存账号为 `test`，密码为 `test123456`。可在服务端运行配置中设置环境变量 `POKEMMO_LOGIN_USERNAME` 和 `POKEMMO_LOGIN_PASSWORD` 覆盖；每次启动重新初始化，不使用数据库、Redis，也不保存账号或登录凭据。认证通过后进入服务器选择窗口。

服务端 VM options：

```text
-Dpokemmo.login.bind=127.0.0.1 -Dpokemmo.login.port=2106
```

项目内置一对本地开发用 P-256 握手密钥，私钥仅随登录与游戏服务模块提供，公钥由协议模块提供。支持用服务端 `-Dpokemmo.login.privateKey=路径` 和客户端 `-Dpokemmo.login.publicKey=路径` 替换为匹配的 DER 文件（私钥 PKCS#8，公钥 X.509）。认证请求使用 UTF-16LE 字符串和 SHA-1 密码摘要，封包使用小端长度头；每次连接独立协商加密密钥，双向分别维护加密流和 HMAC 序号。登录认证后保留连接，用于请求服务器列表及入服凭证；游戏入服成功后客户端释放登录连接。

游戏服务默认监听 `127.0.0.1:7777`，节点 ID 为 `1`，容量为 `100`。运行配置支持：

| 运行配置 | VM options |
| --- | --- |
| 游戏服务 | `-Dpokemmo.game.bind=127.0.0.1 -Dpokemmo.game.port=7777 -Dpokemmo.game.id=1 -Dpokemmo.game.capacity=100` |
| 登录服务中的游戏节点 | `-Dpokemmo.game.host=127.0.0.1 -Dpokemmo.game.port=7777 -Dpokemmo.game.id=1 -Dpokemmo.game.name=PokeMMO` |

两处节点 ID 和端口需匹配。游戏服务未启动时，列表显示“关闭”；启动后列表自动刷新。选择服务器后，游戏服务验证一分钟有效的签名凭证，认证通过则窗口显示已连接的服务器；右上角关闭按钮返回登录页并释放游戏会话。入服凭证消费记录、在线账号和负载只保存在服务进程内存中。

游戏服务私钥可用 `-Dpokemmo.game.privateKey=路径` 替换。两个服务默认共用开发密钥；更换时需保持签名与信任公钥匹配，并在客户端及两个服务配置 `-Dpokemmo.login.publicKey=路径`。游戏心跳使用 `0x20`，每十五秒发送一次；节点探测使用 `0x7E` 扩展封包，经游戏加密通道返回在线人数与容量。

# 关都开场剧情：中文阅读说明

对应同目录的 [opening.json](opening.json)。先读本文即可了解流程，不需要先理解 JSON。

本文说明当前项目的实现，不代表整个关都剧情已经完成。实际对白会随语言资源、ROM 版本变化，下文以对白含义说明。

## 劲敌战身份

首次劲敌战按当前初始选择指定火红原生训练家队伍：玩家选妙蛙种子对应 328（小火龙），选小火龙对应 326（杰尼龟），选杰尼龟对应 327（妙蛙种子）。客户端按地区和训练家编号读取原生身份、训练家类型、名称及立绘；这三条原生记录的立绘编号为 106。参考服务端脚本给出的模型 328 只是占位配置，不能将其低字节 72 当作真实劲敌立绘。旧存档中只记录该模型的首次战斗，根据对方的单只 5 级初始宝可梦补回对应队伍身份。

真实剧情战不应再走随机黑白训练家预览。训练家名称和称号用于开战、派出宝可梦等对白，不能只修立绘。验证用例：`GbaTrainerTest` 与 `KantoStoryUiTest`。

## 初始宝可梦确认界面

调查实验室的精灵球后，`SELECT_STARTER` 使用顶部对白气泡、独立宝可梦动画展示框、下方纵向“是／否”选项，按用户提供的官方截图核对。展示框随当前精灵球切换妙蛙种子、小火龙、杰尼龟；“否”只结束本次确认，“是”才提交领取，服务器继续校验并发放。普通对白和其他确认流程沿用原界面。

`StarterPromptUiTest` 验证三种宝可梦的展示、纵向选项、鼠标接受／拒绝和普通对白恢复；`KantoStoryUiTest` 验证实际领取流程。移动布局在当前屏幕范围内安排展示框和选项，保留移动端气泡主题。

## 博士带路的验收

从真新镇北出口 `(12,1)`、`(13,1)` 分别触发开场，确认对白后玩家和博士以步行速度连续前进，最终进入实验室并到达选初始宝可梦的阶段 2。

带路期间使用剧情步行节奏，不继承强制跑步、自行车或测试倍速；结束后恢复原有移动设置。玩家的路径必须避开博士最终站立的 `(16,14)`，否则博士先到达后会永久挡住玩家。每格到达后立即推进下一格，不额外插入空帧。对应参考服务端 `PalletStoryScene.guide` 的并行动作和完成后切图流程。

自动验证：`OakEscortUiTest` 覆盖左入口 PC、右入口移动布局，检查带路路径、步行模式、停顿和最终实验室阶段；特意开启强制跑步与倍速，防止玩家速度追上博士引发走停。

## 妈妈会说什么？

妈妈在玩家家一楼，地图编号 `4/0`，NPC 编号 `0`。面向妈妈按当前交互键（你的配置为 **Z**）开始对话；点击气泡文字或空白可翻页。

| 玩家状态 | 妈妈的反应 | 对应节点 |
| --- | --- | --- |
| 尚未领取初始宝可梦，男主 | 提醒大木博士正在找你 | `mother_boy` |
| 尚未领取初始宝可梦，女主 | 对应女主的提醒 | `mother_girl` |
| 已领取初始宝可梦 | 让玩家休息 → 治疗队伍 → 告知恢复、叮嘱出门小心 → 结束 | `mother_heal` |

这是 **2 类状态、3 条分支**，不是必须按顺序播放的三个阶段。休息可以重复触发，不会重新发放初始宝可梦，也不会推进开场阶段。

### 休息时具体发生什么？

1. 显示休息对白，其中的玩家名称应显示当前角色名。
2. 玩家确认完这条对白的最后一页后，服务端执行治疗。
3. 队伍 HP 恢复至最大值、PP 恢复、异常状态清除；客户端淡出地图，在黑屏时刷新队伍显示，然后淡入。
4. 动画结束后显示恢复对白；全部翻完后恢复自由操作。

`momDone` 是一条文本资源，但内部可能包含多页。因此“很好，你和你的宝可梦看起来精力十足”和“路上小心”等分页，不一定对应两个 JSON 动作。

治疗完成通知会触发客户端复用的地图淡出/淡入动画（各 500 毫秒）：关闭休息对白 → 地图变黑时刷新队伍 → 地图恢复 → 显示恢复对白。顶部和侧边 UI 不参与变黑，期间不能移动或跳过。参考服务端仅提供治疗和队伍刷新；视觉顺序以用户提供的官方妈妈治疗 GIF 为依据。该动画由通用治疗通知触发，其他 HEAL_PARTY 流程也可复用。

### 为什么旧角色的判断不在 JSON 中？

没有开场记录的旧角色不会自动重置剧情。当前服务端另有兼容处理：队伍中存在非蛋宝可梦就进入休息治疗，否则按性别显示提醒。它位于服务端 `KantoStory.java`，不是 `opening.json` 的分支配置。

## 整段开场按什么顺序进行？

| 存档阶段 stage | 含义 | 如何继续 |
| --- | --- | --- |
| `0` | 尚未触发大木引导 | 在真新镇北出口走到 `(12,1)` 或 `(13,1)` |
| `1` | 大木正在引导玩家 | 跟随大木进入研究所；重连后可恢复引导 |
| `2` | 研究所介绍结束，等待选择 | 与三颗初始宝可梦球之一交互并确认 |
| `3` | 已领取，等待首次劲敌战，或战后告别尚未播完 | 战斗前可触发挑战；战斗已结算时优先接回已保存的告别与离场流程 |
| `4` | 首次劲敌战后的告别与离场已完成 | 自由行动；劲敌已离开，已接入大木的出发提示 |

`stage` 是角色当前进度，存在数据库 `character_kanto_story`；不是改 JSON 就能重置的值。表中没有该角色记录与 `stage=0` 也不是一回事：前者是未登记开场的旧角色，后者是已登记、等待触发的新开场。

另一个存档字段 `starter` 表示初始选择：

| starter | 含义 | 研究所球的 NPC 编号 |
| --- | --- | --- |
| `3` | 尚未选择，不是第 4 只宝可梦 | 无 |
| `0` | 妙蛙种子，物种 ID `1` | `4` |
| `1` | 小火龙，物种 ID `4` | `6` |
| `2` | 杰尼龟，物种 ID `7` | `5` |

NPC 编号、物种 ID、starter 选择值是三种不同编号，不能互换。

## JSON 各部分分别表示什么？

| 字段 | 用普通话理解 | 示例 |
| --- | --- | --- |
| `triggers` | 什么时候、在哪里开始哪段剧情 | 与家中 NPC `0` 交互，进入 `mother` |
| `conditions` | 需要同时满足的条件 | 只有 stage 为 `2` 才能领取初始宝可梦 |
| `actors` | 剧情角色的简称与地图绑定 | `oakLab` 是研究所里的大木 |
| `resources` | 本章用到的宝可梦、招式等资源编号 | 三种初始宝可梦及其选择提示 |
| `nodes` | 一段段剧情流程 | `mother_heal` 是妈妈的休息流程 |
| `actions` | 这一段依次执行的动作 | 说话 → 治疗 → 说话 → 结束 |
| `text` | 白话资源名到文本编号的对应表 | `momRest` 对应 `1627089` |

`text` 里的数字不是直接显示的中文，也不是妈妈第几句话。运行时先找语言覆盖文本；没有覆盖时，从对应 ROM 按版本转换后的地址读取。修改对白内容需要核对语言资源，不能把任意中文直接写到数字字段里。

## 妈妈分支如何读？

```text
与妈妈交互
  ↓
mother：是否尚未选择初始宝可梦？（starter == 3）
  ├─ 是 → mother_choose：判断主角性别
  │         ├─ 男 → mother_boy → 提醒 → 结束
  │         └─ 女 → mother_girl → 提醒 → 结束
  └─ 否 → mother_heal → 休息对白 → 治疗 → 恢复对白 → 结束
```

`BRANCH` 中的 `yes` / `no` 是“条件成立／不成立时跳去哪里”，**不是一定给玩家显示是／否按钮**。

## 本章节点速查

| 节点名 | 作用 |
| --- | --- |
| `town_stop` | 北出口拦住玩家、大木靠近并引导进入研究所 |
| `escort` | 恢复或继续大木引导 |
| `lab_introduction` | 研究所介绍，结束后进入等待选择阶段 |
| `leave_before_choice` | 未选择就想离开时提醒并让玩家返回 |
| `choose_starter` | 显示所选宝可梦的确认提示 |
| `starter_obtained` | 领取后的大木、劲敌对白 |
| `challenge` | 劲敌发出挑战并启动战斗 |
| `battle_complete` | 胜败都先治疗队伍，再显示劲敌告别、走向出口，最后推进阶段 4 并隐藏劲敌；详见 opening.md |
| `mother` | 妈妈对话入口，判断是否已经领取 |
| `mother_choose` | 判断玩家性别 |
| `mother_boy` / `mother_girl` | 领取前的妈妈提醒 |
| `mother_heal` | 领取后的妈妈治疗 |
| `choose_again` | 大木再次提醒选择 |
| `ball` | 球相关的说明对白 |
| `dex` | 图鉴相关说明对白 |
| `aide` | 助手说明对白 |
| `rival_after` | 参考配置中的劲敌后续收尾节点 |

节点存在不等于一定能在当前游戏中触发。例如完成后的劲敌可能已被隐藏；`NOTIFY` 开发通知当前被忽略；首次战斗结算由服务端代码完成。判断实际表现时还要看 `KantoStory.java` 和 `MapEntities.java` 的实现。

## 常见动作与条件速查

| 写法 | 含义 |
| --- | --- |
| `DIALOGUE` | 显示一条可包含多页的对白 |
| `BRANCH` | 判断条件并选择后续节点 |
| `HEAL_PARTY` | 服务端治疗队伍，并通知客户端播放通用地图休息动画 |
| `CLOSE_SCENE` | 结束这段交互、恢复自由操作 |
| `MOVE_PLAYER` / `MOVE_NPC` | 移动玩家／NPC |
| `GUIDE` | NPC 与玩家按引导目标移动 |
| `CHANGE_MAP` | 切换地图 |
| `SELECT_STARTER` | 确认选择并由服务端处理领取 |
| `START_BATTLE` | 启动本章战斗 |
| `SET_OPENING_STAGE` | 按期望的旧阶段更新开场进度 |
| `STORY_STAGE_EQUALS` | 当前阶段等于指定值 |
| `STORY_STAGE_AT_LEAST` | 当前阶段大于或等于指定值 |
| `STARTER_EQUALS` | 初始选择值等于指定值；`3` 表示未选择 |
| `SEX_EQUALS` | 性别等于指定值；本章 `0` 为男主 |

## 怎么在游戏里核对妈妈？

| 测试情况 | 操作 | 应看到的结果 |
| --- | --- | --- |
| 新男角色，未领取 | 回家面向妈妈交互 | 男主提醒对白 |
| 新女角色，未领取 | 回家面向妈妈交互 | 女主提醒对白 |
| 已领取，队伍有损伤 | 与妈妈交互，确认完休息对白 | 队伍恢复，接着显示恢复后的对白 |
| 治疗后再次交互 | 再与妈妈交互 | 可以重复休息，不重复领取宝可梦 |
| 检查姓名 | 查看带称呼的休息对白 | 出现当前角色名，不应是空白 |

不需要为了读懂对话直接改数据库。若要调整流程，先明确改哪一条触发条件或动作；只改本文不会改变游戏逻辑。

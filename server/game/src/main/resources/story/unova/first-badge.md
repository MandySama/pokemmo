对应 `first-badge.json`，区域编号 2。新角色从鹿子镇主角卧室开始；复用现有剧情动作、战斗与存档接口，不执行完整黑白脚本虚拟机。

## 来源

- 参考客户端 `Pokemmo2Pro-Client` 的 `BlackWhiteRom`、`BwMapZoneEvents`、`BwMapHeaderEntry`、`BwTrainerDataEntry`、NPC 贴图映射与帧序。
- 参考服务端没有合众剧情及地图资源，因此按用户允许的回退方式复用本项目关都／丰缘剧情结构。
- 地图和事件来自用户 ROM 的 `a/0/1/2`、`a/1/2/5`；文本来自 `a/0/0/3`；训练家队伍来自 `a/0/9/2`、`a/0/9/3`；NPC 来自 `a/0/4/8`、`a/0/4/9`。JSON 的 `source.romSha256` 标识实际读取的版本，不以网上攻略替换该 ROM 的队伍等级。
- 当前 ROM 文本为英文；尚未与官方应用完整逐幕核对，不能视为官方流程的完整复刻。

## 持久化

`character_unova_story` 保存阶段、初始伙伴、徽章、当前节点与动作序号、恢复位置及一次性标记。动作回复校验序号；战斗只能由战斗结算入口推进。奖励和下一动作在同一事务中保存。断线重进恢复节点；换图回复保存新的位置。奖励、赠送及训练家胜利通过标记避免重复。

## 测试

`UnovaStoryTest` 覆盖三种初始伙伴 × 两种性别、断点恢复、胜负分支、徽章及一次性奖励。`UnovaStoryUiTest` 使用真实 OpenGL 世界和界面测试 PC／Android 布局的开场、礼物选择、实际招式点击及白露战后对白；PC 道馆三个开关通过实际移动触发，随后与馆主交互。截图输出至 `client/build/unova-diagnostics`。运行命令：从仓库根目录执行 gradlew.bat :client:desktop:unovaTest。使用临时数据库，不改动玩家存档。道馆测试预置阶段 13，并在各开关前定位；连通性测试使用真实 MapMovement 与 ROM 碰撞检查卧室至道馆各地图，不含战斗与 NPC 动态阻挡；不代表已经连续自然行走通关。具体通过情况以本次测试报告为准。

# 游戏协议、世界裁决与连接池更新（2026-10-13）

本次按原项目的关键通信和服务端世界处理路径调整，不改变已有账号、密码校验值、角色外观和位置表结构。

## 已完成

| 部分 | 当前行为 |
| --- | --- |
| 游戏校验 | 加密后的封包使用 CRC16/ARC，初值 0、多项式 0xA001、低字节在前；登录仍使用有序号 HMAC-SHA256。 |
| 创建请求 0x03 | 名称 UTF-16LE 零结尾，随后性别、地区、肤色、12 位外观掩码；每个选中槽位为 10 位物品编号与 6 位配色。 |
| 选角与加载 | 0x04 携带角色 ID 与签名混合值，校验归属并确认；客户端随后发送 0x05 请求玩家数据。重选前先排空旧世界存档。 |
| 移动请求 0x06 | 只携带起点 x/y、方向及跑步位；不携带目标地图或客户端计算的终点。 |
| 世界裁决 | WorldSession 持有当前角色位置；FireRedWorldRules 处理起点、地形、高度、固定 NPC 占位、连接偏移、楼梯、门和动态返回点。过快请求或错误起点返回权威位置。 |
| 传送加载 | 目标由服务端事件数据确定，加载确认前暂停移动，30 秒超时断开；客户端准备地图，走入门格后淡出、切图确认、淡入。各淡出／淡入仍为 500ms。 |
| 形态与调试 | 跑步和自行车速度由服务端确认；倍速、穿墙和调试传送走显式请求，服务端 `pokemmo.game.debug=false` 可关闭这三项，当前默认开启。 |
| 存档 | 已接受的位置更新内存；每 200ms 合并变化并异步提交。提交等待不持有世界监视器，数据库暂时阻塞不会阻塞移动裁决；退出串行保存最后位置。显式 flush 只提交服务端状态，客户端不能用快照改写坐标。 |
| 数据库 | HikariCP 6.3.3，最大 8、最小空闲 1、借用等待 10s、验证 5s、空闲 600s、寿命 1500s、保活 120s；归还时恢复连接状态，服务及管理工具负责关闭。 |

## 地图数据

`protocol/src/main/resources/maps/fire-red-world.gz` 保存 425 张地图的通行及事件信息，不包含图像、图块像素或调色板。服务端不依赖客户端模块、ROM 文件或 OpenGL。

导出时应用游戏客户端的增强地图格修正。本次核对发现这些修正影响 121 格阻挡、43 格高度与 39 格行为；直接导出原始模式会造成画面与服务端判定不一致。

可通过客户端类路径运行 `top.totodile.pokemmo.tools.ExportWorldRules <火红ROM路径> <输出.gz路径>` 重建数据；输出后重新构建协议及服务模块。资源对应当前导出卡带及地图规则，不是动态接受客户端上传的通行数据。

## 与原项目的对应关系和保留简化

源码核对对象包括原服务端 `TlsInfo/Crc16`、`CharacterCreationRequest`、`SelectCharacterPacket`、`MovePacket`、`CharacterMovementService`、`CharacterEventService/CharacterWorldLoader` 与 `db.Database`。这些目录没有修改，也没有运行原客户端进行实机互通测试。

CRC 与登录 HMAC 已直接对照原实现计算。创建、选择和移动请求采用对应编码；服务端持有位置、裁决通行和事件、等待加载确认的职责已建立。

角色列表、选角确认的角色结构、玩家加载及世界结果响应仍保留本项目精简数据结构；入服票据也仍使用本项目签名票据。世界扩展为 0x70 显式 flush、0x71 删除、0x72 形态／调试配置、0x73 加载确认、0x74 调试传送、0x75 世界结果。这些不能描述为原客户端全部封包兼容。

周围玩家广播、剧情动态 NPC、完整道具／区域骑车权限和 GM 账号权限体系不在本次接通范围。当前客户端等待服务端响应后插值，尚未实现高延迟环境的预测与回滚。异常强杀仍可能丢失尚未提交的末尾状态。

# GBA 地图与剧情验证

游戏内左侧打开“剧情运行诊断”，使用下拉选择 NPC、事件入口或最近执行记录，点击“刷新状态”。当前入口查询在线角色的 GBA 运行器；离线地图图鉴中的条件切换仍是静态预览。需要同时更新客户端与 game 服务。

查询不会执行 tick、移动 NPC、触发事件、推进对白或写入存档。正常游戏更新仍会继续，因此两次人工查询之间 NPC 可以正常移动。记录最多保留96条，按实际执行顺序排列，重登清空，不进入剧情存档。

## 如何判断

1. 确认地区／地图编号与 ROM SHA-256，避免用不同版本的导出数据比较。
2. 在“NPC当前状态”找到物件编号，比较游戏内坐标、可见性、朝向、活动类型和永久原点。剧情控制为1表示当前由脚本维护；0表示交还日常行为。朝向0／1／2／3为下／上／左／右。
3. 在“事件入口与条件”查看对应脚本入口。变量条件满足仅表示该入口的一项门槛满足，还需考虑地图加载类型、位置、朝向、高度、交互方式和运行器支持范围。背景交互尤其不能仅凭变量行判断。
4. 关闭面板，正常操作触发事件。再次打开并刷新，检查“实际执行入口”、分支是否成立、对白ID和内容、移动入口及逐步动作。变量写入同时记录操作前与操作后的值；标记检查0为未设置、1为已设置。
5. 与导出的 ROM 脚本／地图图鉴对照相同入口及地址，再测试重新入图、重登和剧情回退。只有这一具体路径通过，不能据此宣称整张地图或所有剧情正确。

事件类型0为坐标事件，1～5为地图脚本类型，100以上为背景事件种类加100；地图脚本显示的(0,0)不是实际触发格。NPC活动类型7／8／9／10分别为朝上／下／左／右站立，类型2～6为漫游类型；其他值需查看 ROM 活动类型定义。活动半径是规则边界，不是所有格子都可通行，站立类型即使保留半径也不会漫游。

ROM 动作名称保留原名，例如 WALK_LEFT 表示走左一格、FACE_UP 表示朝上、STEP_END 对应序列结束；指令地址为导出时保留的 ROM 文件偏移。对白显示语言资源解析结果，包含占位符的内容还需结合实际对话窗口核对。记录中的原始字节用于追查尚未展开的物件指令，不把它们当作完整的人类语义解释。

## 真新镇告示牌女孩的可重复用例

先用单独测试角色，避免回退影响自己的剧情。地图为3/0，NPC编号1，原始图形23。

| 操作 | 检查结果 |
| --- | --- |
| 开场边界前，玩家位于(5,16)，入图并等待初始化完成 | 女孩位于(5,15)，活动类型7朝上站立；原点随地图脚本初始化；不是在原始导出格(3,10)漫游 |
| 记录当前位置、版本，再连续刷新 | 查询不改变版本、NPC位置或对白进度；没有生成新的执行记录（正常游戏操作除外） |
| 从(5,16)朝上交互，完整结束对白 | 最近记录包含实际交互入口、条件结果、对白和移动；女孩左移到(4,15)，永久原点更新为(4,15) |
| 等待、再次交互 | 保持站立，不因交还日常逻辑重新漫游；重复交互走当前条件分支 |
| 退出客户端再登录 | 保留剧情后的坐标、活动类型及原点；最近记录重新开始，不能把旧记录误认为本次执行 |
| 在剧情指令中回到开场之前，再返回真新镇 | 女孩恢复开场地图初始化的位置与站立类型，不沿用旧日常缓存 |
| 在另外的测试状态从不同方向交互 | 对照分支记录及原始脚本，按玩家方向检查实际让路方向，不假定所有分支都向左 |

## 自动验证

- `tools/tests/ScriptDiagnosticSmoke.java`：读取不改存档、版本和日常 NPC；封包边界；原始女孩对白、分支及移动；记录有界且不持久化。
- `tools/tests/ScriptDiagnosticNetworkSmoke.java`：隔离 PostgreSQL 账号、真实加密 TCP；实际角色状态查询、女孩交互、重登及回退；结束删除测试账号。
- `tools/tests/ScriptDiagnosticUiSmoke.java`：隐藏窗口中的真实 OpenGL／TWL，检查布局、尺寸和手动刷新，截图位于 `target/script-diagnostic.png`。

这些测试覆盖所列路径，不代表原客户端实测，也不证明全部地图或全部特殊函数已实现。
